# FDA food backfill runbook

## Current state

Recall Radar currently ships 100 FDA/openFDA food enforcement records from the static source file generated by the existing FDA fetch pipeline. The canonical merged source file contains 1101 records across the current nine sources.

Phase 22 confirmed that openFDA currently reports about 29,171 food enforcement records, and that individual records such as `H-0950-2026` parse correctly through the existing FDA normalizer. The current gap is source selection and sample size, not parser failure.

## Why full backfill is not run now

Full historical FDA backfill is intentionally deferred because it would add thousands of records, increase static build output, change search behavior, and require source quality review. This phase only adds bounded dry-run tooling, ignored output paths, checkpoint structure, and audit scripts.

Do not run broad source update scripts, `build:data`, or canonical merge commands as part of FDA backfill preparation.

## Safe dry-run command

```bash
npm run backfill:fda-food
```

This defaults to dry-run mode. It fetches a bounded latest sample, prints a structured JSON report, and writes no chunk files.

## Sample date-window command

```bash
npm run backfill:fda-food -- --from-date=20260101 --to-date=20261231 --max-pages=2
```

This stays dry-run by default. It fetches a bounded date-window sample and reports counts, duplicate signals, date ranges, and sample normalized records.

## Small local test backfill

```bash
npm run backfill:fda-food -- --dry-run=false --write-chunks=true --write-checkpoint=true --from-date=20260101 --to-date=20260131 --max-pages=1
```

This creates ignored local output under `data/backfill/fda-food/`. Do not commit generated chunks, manifests, checkpoints, or logs.

## Checkpoint and resume

When `--write-checkpoint=true` is used in non-dry-run mode, the script writes a checkpoint to:

```text
data/backfill/fda-food/checkpoints/fda-food-backfill-checkpoint.json
```

The checkpoint stores the date window, last successful page, last skip, next skip, record counts, completion flag, and warnings.

To resume from the checkpoint:

```bash
npm run backfill:fda-food -- --dry-run=false --write-chunks=true --write-checkpoint=true --resume=true --from-date=20260101 --to-date=20260131
```

Resume is optional and should only be used for local ignored output.

## Ignored output directories

Generated FDA backfill output is ignored by `.gitignore`:

```text
data/backfill/fda-food/**/*.json
data/backfill/fda-food/**/*.jsonl
data/backfill/fda-food/**/*.tmp
data/backfill/fda-food/**/*.log
```

Only tiny documentation placeholders such as `data/backfill/fda-food/README.md` or `.gitkeep` may be committed if needed. This phase does not require them.

## Audit backfill output

```bash
npm run audit:fda-food-backfill
```

If no ignored chunks exist, the audit passes with:

```text
No FDA backfill chunks found; nothing to audit.
```

If sample chunks exist, the audit checks JSON parsing, records array shape, normalized fields, FDA source ids, duplicate recall numbers, duplicate event ids, duplicate normalized ids, invalid dates, missing recall numbers, category counts, classification counts, status counts, and slug collisions.

## Future canonical merge

Future canonical FDA expansion should be a separate reviewed phase. It should:

- select a bounded launch subset before any broad historical expansion
- deduplicate by `recall_number`, then `event_id`, then normalized id
- normalize with `extractFdaFoodRecords()` and `normalizeFdaFoodRecords()`
- audit required fields and source counts before merge
- verify static route count, build time, search quality, and source filter stability
- update canonical files only after review approval

## Launch-time checklist

- Confirm intended FDA backfill scope and selection policy.
- Run dry-run date windows before writing chunks.
- Run a tiny local ignored chunk write test.
- Run `npm run audit:fda-food-backfill`.
- Confirm no generated chunks are staged.
- Confirm canonical count changes are intentional and reviewed.
- Run source, image, country, check, build, and launch validation.

## Rollback plan

Because generated chunks are ignored and canonical merge is disabled by default, normal rollback is to delete local `data/backfill/fda-food/` output and rerun the dry-run. If a future phase intentionally changes canonical processed data, rollback should restore the previous committed canonical data files and rerun the full audit suite.

## FDA image limitation

The openFDA food enforcement JSON used here does not provide usable product image URLs. This pipeline does not add FDA image scraping, press-release scraping, proxying, downloading, or CDN behavior.

## Do not commit generated output

Before any commit, run:

```bash
git status --short
```

Generated files under `data/backfill/fda-food/` must remain untracked and ignored.
